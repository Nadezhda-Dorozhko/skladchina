# Лабораторная работа №4. Управление состоянием в React

Клиентская часть курсового проекта «Складчины» (предметная область из лабораторных №1–3).
Приложение автономное: данные хранятся в `localStorage`, сервер не нужен.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # production-сборка
npm run lint
```

## Что реализовано

| Требование задания | Где в коде |
| --- | --- |
| Компонент управления списком | `src/components/PurchaseList.jsx` |
| `useState`: массив, поле ввода, фильтры | `useLocalStorage` (массив), `PurchaseForm` (поля формы), `PurchaseList` (фильтры, `editingId`) |
| `useEffect` с `[]` — загрузка из localStorage при монтировании, иначе начальные данные | `src/hooks/useLocalStorage.js` |
| `useEffect` с `[items]` — сохранение при каждом изменении | `src/hooks/useLocalStorage.js` |
| Добавление, редактирование, удаление | `PurchaseList` + `PurchaseForm` |
| Фильтрация и сортировка | `Filters.jsx`, `useMemo` в `PurchaseList` |
| Заголовок страницы от количества элементов | `useEffect` в `PurchaseList` |
| Автосохранение с debounce 500 мс | черновик формы, `PurchaseForm` |
| Имитация загрузки с сервера (1 с) | параметр `loadDelay` хука, спиннер в списке |
| Статистика | `Stats.jsx` |

Логика работы с `localStorage` вынесена в пользовательский хук `useLocalStorage`,
чтобы в лабораторной №5 заменить его на запросы к REST API, не меняя компоненты.

## Модель данных

Поля совпадают с моделями из лабораторной №3 (`Purchase`, `Participant`):

```js
{
  id, title, description, organizer,
  targetAmount, currentAmount, deadline,   // deadline — YYYY-MM-DD
  status,                                  // "active" | "completed"
  category,                                // продукты | хобби | техника | одежда | книги | другое
  participants: [{ id, name, contribution }]
}
```

Статус вычисляется автоматически: когда `currentAmount >= targetAmount`, складчина становится «Завершена».

## Обработка особых случаев

- **Ключа нет в localStorage** — загружаются 4 демонстрационные складчины.
- **Данные повреждены** (невалидный JSON) — предупреждение в консоли и возврат к начальным данным.
- **Пользователь удалил всё** — пустой список сохраняется и не подменяется демо-данными; есть кнопка «Загрузить демо-данные».
- **Сохранение до завершения загрузки не выполняется** — иначе пустой массив затёр бы сохранённые данные.
- Таймеры в эффектах очищаются (важно для `React.StrictMode`, который монтирует компоненты дважды).

## Ключи localStorage

- `skladchina:purchases` — список складчин;
- `skladchina:draft` — черновик формы новой складчины.

## Тестирование (чек-лист)

1. `npm run dev` — 1 секунду виден спиннер, затем 4 карточки; вкладка называется «Складчины: 4 (активных: 3)».
2. Добавить складчину (пустая форма показывает ошибки валидации) — карточка появляется сверху, заголовок вкладки обновляется.
3. «Редактировать» → изменить название → «Сохранить изменения».
4. «Участники» → добавить участника с взносом — растут сумма и прогресс; при достижении цели статус становится «Завершена».
5. Поиск, фильтр по статусу и категории, сортировка; кнопка «Сбросить фильтры».
6. «Удалить» с подтверждением.
7. Начать заполнять форму, подождать 0,5 с — появится «Черновик сохранён»; перезагрузить страницу — поля восстановлены.
8. Перезагрузить страницу — список и изменения на месте.
9. DevTools → Application → Local Storage — ключи `skladchina:purchases` и `skladchina:draft` содержат корректный JSON.
10. Записать в `skladchina:purchases` значение `{bad` и перезагрузить — приложение показывает демо-данные, а не падает.
